## 1 Fit View 回归（严重，04c）

### Root cause
1. **小地图黄框被 clamp 成「谎言」**：`Math.max(vpMapX/Y, 0)` + `Math.min(vpMapW/H, mapSize)` 在视口偏离内容时，黄框仍铺满小地图，看起来罩住全部节点，主视口却是空的（clean-1613 04c 笔记：DOM `y -1677..-1058` 全在屏外，缩放约 32–40%）。
2. **Fit 只对「整容器」做安全校验，不对「去掉顶栏/底栏/侧栏后的可用区」循环降缩放**：换到 z-image 后节点变高（Schema 控件 + 预览图），一次 Fit 在可用区可能仍裁切；再叠加缩放按钮只改 `scale`、不绕视口中心（旧实现），内容容易漂出可用区。
3. **graph 模式小地图仍画 leftover spatial frames**，与 Fit View（nodes only）bbox 不一致。
4. **左右浮动层未计入 insets**（执行记录条/面板、小地图），Fit / 自动平移后节点标题、红框、字段标签仍被顶栏/底栏/侧栏压住。

### Fix
- `computeFitTransform`：过滤非法 box；在可用区内校验，不通过则把 `minScale` 减半最多 6 次，底线 0.01。
- `allItemsInUsableBox` + `measureChromeInsets` 读 `top/bottom/left/right`；打开的执行记录面板也计入 left。
- `fitItemsForMode` 可测 DOM 宽高；`handleResetView` rAF 二遍：若 `getBoundingClientRect` 仍在可用区外则再 Fit 一次。
- 缩放按钮改为绕视口中心缩放（避免 Fit 后再漂走）。
- Minimap：黄框不再 clamp；graph 模式不画 leftover frames；`data-canvas-chrome="right"`。

Files: `src/utils/fitView.ts`, `src/App.tsx`, `src/components/Minimap.tsx`.

## 2 拦截后自动平移 + 执行记录（严重）

### Root cause
1. **`recordLocalEvent` 默认 `state:'error'`** → 执行记录打成「请求失败」「较早失败」红样式；平移不是请求。
2. **记录写在 `setTransform` updater 里** → React StrictMode 同一 prev 双跑 → **两行重复**（16:32:33 双行）。
3. **`setTimeout(60)` 在 `finally { endRun() }` 之后才写记录** → `currentRunLabel` 已清空 → 挂到 **「未归属运行」**，而不是当次第 N 次运行。
4. **reveal 未计入 left/right chrome**：原因节点被打开的执行记录面板挡住时，可能被判「已在可用区」→ **当次不平移**（run 8：手拖顶替）。

### Fix
- 在 `catch` 里、`endRun` 前 `currentRunAttach()` 捕获 `runSeq/runLabel/runTarget`。
- `recordLocalEvent(..., 'complete', now, attach)`；`recordedPan` 守卫只写 **一行**。
- **先写记录再 `return next`（跳视口）**。
- `revealNodeTransform` 接受 `left/right`；App 传入 `measureChromeInsets` 全量 insets。
- ExecutionLog：`isViewportPanRecord` → 中性样式 +「视口操作 · 0 个请求」；不打失败标签。

Files: `src/services/executionTrace.ts`, `src/utils/localBlock.ts`, `src/App.tsx`, `src/components/ExecutionLog.tsx`.
