## 1 Toast = 「HTTP <code>」 + upstream body verbatim
- Root cause: App.tsx catch → generic `{title:'请求未完成', message: runToastLine()+'；'+errMsg}`; runToastLine (「本次请求未含 LoRA：…」) came first and hid the 402 body.
- Fix: `upstreamFailureParts` / `upstreamFailureToast` (src/utils/apiFailure.ts) are the single source, shared with `upstreamHttpFirstLine`. Title `HTTP <status>[ statusText]`; first line = upstream body's first line verbatim (cut at 400 chars + 「…（已截断，展开看完整原文）」); if cut or multi-line, the full body appears under 「完整上游响应原文」 in the 展开全文 details; the last line is 运行：<节点>. The LoRA prefix is not used for upstream HTTP failures. Non-HTTP errors keep the old toast.
- Files: src/utils/apiFailure.ts, src/App.tsx.

## 2 Load LoRA node shows 本地拦截 · 未发请求 (shared copy)
- Root cause: only the output node rendered the line (NodeItem output section), using a hardcoded string. Branch nodes (LoRA) already got `upstreamLocalBlocked`, but no widget displayed it.
- Fix: `LOCAL_BLOCK_NODE_LINE` (built from `LOCAL_BLOCK_TOAST_TITLE`) in apiFailure.ts. NodeItem renders `data-testid="node-local-block"` in the body of every blocked-branch node (incl. LoRA), and the Save node uses the same constant. ExecutionLog's bar uses `LOCAL_BLOCK_TOAST_TITLE`.
- Files: src/utils/apiFailure.ts, src/components/NodeItem.tsx, src/components/ExecutionLog.tsx, src/App.tsx (comment).

## 3 Four field states, no 待确认
- Root cause: SchemaChoiceControls showed 「待确认」 for unfilled fields when not liveConfirmed/schemaUnprobed. The not_sent badge read 「该端点不支持」.
- Fix: `schemaFieldBadge(current, schemaDefault)`: filled → 会发送 v; unfilled → `未填写，不发送（Schema 默认：x）` only when the Schema declares a scalar default, else `未填写，不发送`. The same text is used for the select's empty option and the number placeholder. FieldStatusBadge `not_sent` → `Schema 不支持，不发送`; `schema_unavailable` stays `Schema 不可用，字段不会发送`.
- Remaining non-four state: FieldStatusBadge `pending` (KSampler badges when the Schema has not been fetched yet, since nothing fetches on mount) is relabelled `Schema 未读取，发送情况未知`. See the open question in the report.
- Superseded tests updated: venicePostfix (schemaFieldBadge) and veniceReverifyUi (the old 「待确认」 contract).
