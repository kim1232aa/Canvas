## 1 Toast first line = upstream raw body only
- Root cause: on the Together Schema GET, the server's `read()` throws, and `fail()` answers `{ok:false,error:"HTTP 401: …",rawResponse,endpoint,stack}`. `schemaPrefetchFailureData` only recognised `upstreamStatus/upstreamResponseBody`, so it fell through to using the whole wrapper as the "upstream body". The toast's first line therefore showed the wrapper JSON, with `\"` escapes, a local path and the stack.
- Fix: when the wrapper has `rawResponse`, the upstream body is `rawResponse` verbatim. The wrapper is only JSON.parsed, which removes the outer escaping; the upstream text is unchanged. The wrapper and stack go into `localWrapper` and appear only in the expanded section, under 「本地包装与堆栈（技术详情）」. The fallback that parses the legacy error message unwraps the same way.
- Files: src/engines/drivers/SchemaProviderDriver.ts, src/utils/apiFailure.ts. Tests: #1 (2).

## 2 Node badges after a failed Schema GET → 「Schema 不可用，字段不会发送」
- Root cause: node badges call `schemaSendStatus(provider, field, value, node.values.custom_parameters, declared, schemaCustomParameters)`. The engine's Schema state (`_canvas.schemaUnavailable`, set by `withCachedSchemaProperties`) arrives in the 6th argument, `schemaMeta`. The `schemaUnavailable` / `schemaLoading` flags were only read from the 4th argument, the node's own custom_parameters, and KSampler / Empty Latent have none, so the result fell to `pending` (「Schema 未读取」). The right panel passes the engine JSON as the 4th argument, which is why it was correct.
- Fix: the flags are read from both the node's own JSON and `schemaMeta`, with unavailable taking priority over loading.
- Files: src/utils/schemaSendStatus.ts. Tests: #2 (2).

## 3 z-image/turbo sent `size "1024*1344"` while the canvas height was empty
- Search: `rg 1344` finds no hard-coded fallback in server or graph code. The only hits are the zImageSpace preset list and the ParameterInspector 21:9 preset (1344×576).
- Size assembly: the server's `schemaProviders.ts` packs `${width}${sep}${height}` into `size` only when the official Schema declares `size` as a "W*H" string. It uses the request body's width/height exactly as given, and adds nothing from the Schema default.
- Root cause: the canvas's own fallback in `graphEngine.extractWorkflowParameters`. The intent was "use the Checkpoint node's width/height when no Empty Latent is connected", but the code ran `if (height === undefined) height = ckpt.values.height` even when an Empty Latent was connected and its height was simply empty. The Checkpoint node still held a stale `height: 1344` written back by the panel (App's inspector write-back persists `width`/`height` onto the checkpoint node), so 1344 was sent while the canvas showed an empty height.
- So the value is a stale node value, not the Schema default, not an aspect_ratio mapping and not a hard-coded global fallback.
- Fix: the Checkpoint size is used only when no Empty Latent is connected (`latentSizeSource`). With a connected Empty Latent, an empty field stays empty. If only width is filled, the server's existing rule blocks locally (「画布只填了宽或高之一；未发送请求，未自动补值」), so what is sent matches what is shown.
- Files: src/utils/graphEngine.ts. Tests: #3 (2).

## 4 One Schema GET per model
- Root cause: `noteUserModelSelection` called `beginSharedGetAction()` and started a new operation on every call. Any repeat for the same model opened a new action and sent a second GET: the select's onChange, then a blur or Enter on the custom-ID input that commits the same value, a hub re-apply, or a node sync. That matches operations 19 and 20, 27 s apart.
- Fix: if the provider and model are the same as last time and a shared result exists, that result is reused (success or failure), with no new action and no new operation. A different model, or an explicit force button (刷新目录 / 读取官方 Schema), still fetches.
- Files: src/services/userModelSelection.ts. Tests: #4 (mocks fetch; the same model twice gives 1 GET, a different model gives 2).
