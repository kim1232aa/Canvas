## 用到的官方端点
| 用途 | 端点 |
|---|---|
| 模型中心目录 | `GET https://api.krea.ai/openapi.json` → 取 `POST /generate/image/*`、`/generate/video/*` 操作；每个操作 = 一个模型端点，requestBody schema 即参数 Schema |
| LoRA 中心 | `GET /styles?limit=&model=`（官方 "Search styles"；返回 `items[{id,title,models,cover_url,owner}]`） |
| 生成 | `POST /generate/{image\|video}/{vendor}/{model}`，返回 `job_id` |
| 轮询 | `GET /jobs/{id}`，`status` ∈ backlogged/queued/…/completed/failed/cancelled，结果 `result.urls` |
| 设置页 Key 测试 | `GET /styles?limit=1`（`/usage` 需 workspace service key / 套餐权限，返回 403，不适合作测试） |

## LoRA：官方支持（按模型）
OpenAPI 中部分模型（如 `bfl/flux-1-dev`、`krea/krea-2/*`、`z-image/z-image`）requestBody 含
`styles: [{id: string, strength: number ∈ [-2,2]}]`，描述 "Styles (typically LoRAs) to use for the generation"。
- 映射：画布 LoRA 节点 → `styles[{id,strength}]`；id 来自 `/styles` 目录（或手填 style ID）。
- 端点 Schema 无 `styles` → **直接 400 拒绝提交**（不静默剥离）；强度越界 [-2,2] → 400。
- 模型中心条目 `supportsLora` 由该端点 Schema 是否含 `styles` 决定。

## Live smoke（服务端，经 `/api/models`、`/api/schema-provider/krea/submit` 真实路由）
结果文件：`/workspace/canvas/temp/canvas-e2e-archive-20261017/canvas-e2e-krea/smoke-key0.json`、`smoke-key1.json`
| 步骤 | Key#0 | Key#1 |
|---|---|---|
| 目录 `GET /openapi.json` | 200，34 个图像端点 | 200 |
| LoRA `GET /styles?model=flux_dev` | 200（取 200 条） | 200 |
| 生成 `POST /generate/image/bfl/flux-1-dev` + `styles:[{id:"79tzf61yz",strength:0.8}]` | **402** | **402** |

402 原文：`{"message":"Your API balance is separate from your workspace compute balance. Please top up your API balance to continue using the API."}`

实际请求体（已含 LoRA）：
```json
{"prompt":"a lighthouse on a cliff at sunset, watercolor","width":1024,"height":1024,"steps":25,"seed":42,"styles":[{"id":"79tzf61yz","strength":0.8}]}
```
注：最初整串 `KREA_API_KEY`（含逗号）作为单 Key 得 401；服务端 Key 池本来按逗号拆分，故实际运行不受影响。
