## 1) 执行记录残留 402

**根因**
- `beginRun()` 只清 `state==='error'`，但**取景框 SpatialFrame 出图路径从未调用 `beginRun`**，换供应商也不清执行记录。
- 因此上一轮 Krea「Your API balance is separate…」会一直挂在左下角，直到（有时永远不会）走工作流 `handleExecute`。

**改动**
- `src/services/executionTrace.ts`：导出 `clearExecutionErrors()`；`beginRun` 同时丢掉 error + 卡住的 pending。
- `src/App.tsx`：SpatialFrame 开跑时调用 `beginRun()`；`targetProvider` 切换时 `clearExecutionErrors()`。

**测试**：`batch0503.test.ts` · beginRun / clearExecutionErrors

## 2) Venice LoRA Hub 文案自相矛盾

**根因**
- `fetchSchemaProviderRows(venice, {lora:true})` 返回空行，却把**模型目录** `…/models?type=all` 塞进 `sourceUrl`。
- UI：`后端没有可调用的目录接口` + `（来源：/models?type=all）`。

**改动（通用）**
- 无声明 LoRA 目录的供应商：`noLoraCatalog:true`，**不设** model-catalog `sourceUrl`；notice＝「无 LoRA 目录接口（仅 lora_strength）」等。
- `catalogEvidenceFrom`：见 `noLoraCatalog` 时不展示 endpoint。
- `getSchemaProviderCatalog(type=lora)` 同样不泄露模型目录 URL。

**测试**：`batch0503.test.ts` · catalogEvidenceFrom / fetchSchemaProviderRows(venice,lora)

## 5) Flux2 Dev AIR 本地 400 + 历史「未发送」误标

**根因（E2E `/workspace/canvas/temp/canvas-e2e-archive-20261017/canvas-e2e-civitai-flux2/outcome.json`）**
1. LoRA 节点 `lora_name`＝AIR，但 `civitai_id:""`，`download_url` 仍是旧 HF krea2_darkbrush。

- `resolveHistoryParameters` + `buildLocalRejectionHistoryItem` + `schemaFieldWires`：local_blocked 用 Schema wires 区分不支持/未发送。

**测试**：`batch0503.test.ts` · AIR sync / empty civitaiId / history labels
