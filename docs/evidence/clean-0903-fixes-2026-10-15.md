## 1. Duplicate Schema GETs within one action
**Root cause.** `sharedGetJson` deleted failed entries. After a 401, every other caller in the same action fetched again: the node editor, the inspector editor, the badge cache, and the driver's own `request()`. The driver did not use the shared memo at all.

**Fix.**
- `src/services/sharedGet.ts`: the memo is scoped to an action epoch. Results are kept for the epoch, failures included. `beginSharedGetAction()` starts a new action; `force` covers an explicit refresh.
- `peekSharedGet()` reads the stored result without fetching. `subscribeSharedGet()` notifies listeners.
- `SchemaProviderDriver` makes its Schema GET through `sharedGetJson` with the same credential headers.
- `App.tsx` calls `beginSharedGetAction()` at both run starts. `ProviderModelSelect` calls it when the user picks a model.
- The old test "failures are not memoised: next call retries" now reads: failures are memoised for the action, and the next action retries.

**Tests.**
- `src/server/postfix0615.test.ts`: the updated failure-memo test.
- `src/utils/clean0903.test.tsx`: counts fetches across mount, selection and run, for Schema 200 and Schema 500. Mount: 0. Selection: 1. Run: exactly 1 more.

## 2. No fetch on mount or hydrate
- `ensureModelSchema` no longer fetches. It mirrors the shared GET result. Only an injected `fetchImpl` (used in tests) fetches.
- `ApiParameterEditor` only peeks on its first effect. It fetches only on a provider or model change after mount, or when 读取 Schema is clicked.
- `ProviderModelSelect` does no catalog GET until armed. Focus, mousedown, typing, 刷新目录 or a provider change arm it.
- Other providers use the same two components. A scan found no other mount-time Schema or catalog fetch. `fetchHistory` on mount is local history, not Schema or catalog. The model hubs fetch only when the user opens them.
