## 1 Together Schema GET 401 toast = generation POST toast
- **Root cause:** `SchemaPrefetchError` was a plain `Error` with message `GET … → HTTP 401 · 生成 POST 未发送\n<body>`. App catch fell through to `{title:'请求未完成', message: runToastLine()+'；'+errMsg}`, so the user saw 「请求未完成 / 本次请求未发出生成请求：GET …」 instead of 「HTTP 401」 + upstream body.
- **Fix:** `schemaPrefetchFailureData` + `error.data` on prefetch failure (`SchemaProviderDriver.ts`). Shared `toastFromRunError` / `upstreamFailureToast` (`apiFailure.ts`): title `HTTP <code>`; first line = upstream body verbatim (cut at 400); full body under 展开; no LoRA / 「未发出生成请求」 prefix. Recovers from legacy message text if `.data` missing.
- **Files:** `src/engines/drivers/SchemaProviderDriver.ts`, `src/utils/apiFailure.ts`, `src/App.tsx`.

## 2 Apply custom JSON → zero `/api/models?query={…}`
- **Root cause:** Catalog `query` accepted a JSON object string (custom_parameters, often with `_canvas`). The only writers of `query` are the search inputs (`ProviderModelSelect` / hubs). Pasting or routing that JSON into `query` produced `GET /api/models?query=%7B…%7D`. Node write paths (`ApiParameterEditor` / `SchemaChoiceControls` `onChange`) only update `custom_parameters` and do not call `fetchLiveModels`.
- **Fix:** `isCustomParametersJsonQuery` / `sanitizeCatalogQuery` at `fetchLiveModelsOnce` (all callers). `ProviderModelSelect` refuses JSON-shaped query (clears it, **no fetch**). Status when a model is already selected: 「已选底模」 (item 9).
- **Files:** `src/services/api.ts`, `src/components/ProviderModelSelect.tsx`.

## 3 History 尺寸 row: no struck label, no duplicate
- **Root cause:** `formatHistorySize` put the source label into `text` when there was no canvas value; the UI then struck `text` **and** rendered the chip → 「尺寸：该端点不支持 · 未发送」(struck) + 「⊘ 该端点不支持 · 未发送」.
- **Fix:** `formatHistorySize` returns `{ text, canvasValue?, source }`. UI shows canvas value (struck only if `unsupported`) + one chip; label never struck. Chip style remains dashed rose (no line-through) from clean-1029.
- **Files:** `src/utils/historyParameters.ts`, `src/components/HistoryModal.tsx`.

## 4 Exec log: LoRA Hub not named 「第 N 次运行」
- **Root cause:** `beginRun` also called `beginTraceOperation('第 N 次运行')`, so later GETs inherited that `opLabel` until another operation began. Opening LoRA Hub / 底模中心 never started an operation.
- **Fix:** `beginTraceOperation('打开 LoRA Hub')` on CivitaiModal open; `beginTraceOperation('打开底模中心')` on ModelHubModal open. Other non-run ops already named (选用模型 / 切换服务商 / 打开模型目录 / 刷新目录).
- **Files:** `src/components/CivitaiModal.tsx`, `src/components/ModelHubModal.tsx`.
