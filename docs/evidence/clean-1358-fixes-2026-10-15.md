## 1 Fit View（严重）空视口
- **Root cause:**
  1. `minScale` default was **0.35**. When the fit bbox was larger than ~3× the usable box (wide graph, leftover spatial frames included in the same bbox, etc.), scale clamped to 0.35 and **every node could sit outside the viewport** (reproduced: nodes + orphan frame at 8000,5000 → vis=0).
  2. `handleResetView` always unioned **nodes + spatialFrames**, so graph mode was poisoned by leftover frames from an earlier spatial session / workspace cache.
  3. Node height was hardcoded to `350`, ignoring real DOM height.
  4. Minimap yellow box used `window.innerWidth/Height` while Fit View used the canvas container → yellow box and nodes disagreed even when Fit was correct.
- **Fix:**
  - `minScale` default **0.05**; if anything is still outside after fit, refit once with 0.01.
  - `fitItemsForMode(mode, …)`: graph → nodes only; spatial → frames (fallback nodes).
  - Measured `offsetHeight` when the node is in the DOM.
  - Minimap viewport + click-to-center use `[data-testid="canvas-container"]` client size.
- Files: `src/utils/fitView.ts`, `src/App.tsx`, `src/components/Minimap.tsx`.

## 2 Venice 选模型疑似双重 Schema GET
- **Root cause (查清):** **浏览器只发了 1 次** `GET /api/model-schema`. 服务端 `modelSchema('venice')` **故意**拉两份**不同**的上游资源来组装定义：
  1. `GET …/api/v1/models?type=all`（目录 + per-model constraints）
  2. `GET …/doc/api/swagger.yaml`（官方 request Schema）
  上游日志两条 route 都是 `/api/model-schema`，时间差 0.17s，对应同一次 handler 里的两次 `dep.fetch`，**不是**浏览器双发，也不是同 URL 读两次。
- **Fix:** 进程内 `officialSpecCache` 按 URL 缓存官方 OpenAPI。同一进程内第二次选模型（换模型 / 再读）不再重复拉 swagger；目录仍每次实读（保留「刷新 / 新的 GET /api/model-schema 读上游」语义）。冷启动第一次 Venice 选模型仍会看到 2 条不同 upstream URL —— 这是 Venice Schema 组装所需，不是双发 bug。
- Files: `src/server/schemaProviders.ts`.
