## 1. 五条铁律（用户定的，不可协商）

1. **调查与断言原则**：任何 API/库事实先调查（web 搜索、官方文档、真实请求），严禁凭记忆断言。
2. **严禁静默容灾与虚假成功**：不得偷偷换供应商/端点/模型；错误必须原样透传（HTTP 状态码 + 响应体 + stack）。
3. **严禁 Fallback 掩盖错误**。
4. **严禁硬编码集成**：动态配置，通用 API Schema 驱动。
5. **严禁黑盒**：所有调用流、参数转换必须可见可追溯（前端「执行记录」面板 + 服务端 `logs/upstream.log`）。

## 2. 验收标准（用户原话的落地解释）

- 绿勾/测试通过/构建通过**都不是**验收标准，**前端跑通出图才是**。
- 能生成的供应商**必须真实出图**，且：带参数（seed/steps/size 等）、带工作流快照（workflowSnapshot）、带 LoRA 参数（符合该端点真实能力）。
- 底模中心 / LoRA 中心 / 节点下拉框的模型必须来自**实时目录**，数量与官方一致，可刷新，无硬编码清单。
- 欠费不算失败（记 PASS_BILLING）；环境不通记 BLOCKED_ENV；凭证无效记 BLOCKED_AUTH。
- 判定等级（HANDOFF.md §3.1）：`PASS_GENERATION / PASS_BILLING / BLOCKED_AUTH / BLOCKED_ENV / FAIL_INTEGRATION / NOT_TESTED`。

## 4. 环境与运行

### 4.1 硬要求
- **Node 22**（undici 8 依赖；Node 20 不行）。
- 安装依赖：`npm install`；启动：`npx tsx server.ts`（或 `npm run dev`）。
- 验证命令：`npx tsc --noEmit` / `npx vitest run` / `npm run build`。

### 4.2 密钥管理（红线：永不进 git/截图/日志）
- 各供应商 key 向项目所有者索取（本轮验收使用的 key 由用户直接提供，未入仓库）。
- 运行时两条通路：服务端环境变量（`CIVITAI_API_KEY`、`FAL_KEY`、`HF_TOKEN`（逗号分隔多 key 池）、`MODELSCOPE_TOKEN`、`MODELSCOPE_AI_TOKEN`、`NANOGPT_KEY`、`TENSORART_API_KEY`、`MUAPI_KEY`、`WAVESPEED_KEY`、`SOGNI_KEY`、`SENSENOVA_KEY`、`SENSENOVA_BASE_URL`）；或前端「API 与密钥设置」面板（存浏览器 localStorage `comfycanvas_api_keys`，逐请求以 `x-<provider>-key` 头发送，本地优先保存、云端同步失败不阻塞本地——B01 修复后行为）。
- 日志里只应出现掩码（如 `wsk_...awlI`）。发现明文立刻删改。

## 5. 前端验收方法

前端验收 = 真实浏览器打开应用，用 UI 完整走「选底模 → 选 LoRA → 填参数 → 运行工作流 → 看执行记录/出图」。自动化工具不限（本轮用 CDP 驱动 Chromium），但以下 UI 事实已实测，照此定位元素，勿猜：

- 画布节点 class 是 `.canvas-node`（**不是** `.react-flow__node`）。
- 底模中心自定义模型输入框 `#custom-tensor-template-input-modelhub`；Fal 底模按 ID 选用框 `input[placeholder*='fal-ai']`；LoRA 中心 Fal 页签自定义输入框 `input[placeholder*='LoRA path']`。
- API 参数 JSON 框 `textarea[aria-label="自定义 API 参数 JSON"]`。
- React 受控输入框须派发原生 input/change 事件（原生 setter + `new Event('input',{bubbles:true})`）。
- 屏外元素先 `scrollIntoView()` 再点击；`alert()` 会阻塞自动化截图，需处理原生弹窗。
- **「清空画布」「重置为默认工作流」菜单项走原生 `confirm()`**：无头/自动化环境下弹窗不显示、点击静默无效，需注入 `window.confirm = () => true` 后再点。
- 执行记录条目的展开钮是 `<summary>`（details/summary 结构）；底部状态胶囊「执行记录 · N」点开追踪面板。
- 画布状态持久在浏览器 localStorage（`comfycanvas_boards_v2` 等），刷新不丢。
- LoRA 接入工作流必须用「选用 LoRA · 保留当前底模」（接入现有链）；「新建节点」产生的孤立 LoRA 节点不参与请求（会发 `loras: []`，属无效验收证据——F05）。

## 8. 排查发现（待决策/待修）

| 编号 | 发现 | 状态 |
|---|---|---|
| F01 | **Civitai 权重下载需鉴权**：`https://civitai.com/api/download/models/{versionId}` 无 token 返回 401。Fal 服务端拉取 LoRA 拿不到 Civitai 文件；本项目又按设计**不把 Civitai token 拼进发给 Fal 的 URL**（防泄漏）。→ Fal + Civitai LoRA 组合在当前设计下不可用，需改用 HF 直链或 Fal 托管 LoRA | 📋 记录（设计约束，非 bug） |
| F02 | **LoRA Hub 自定义导入（Fal 页签）对 URL 的处理缺陷**：`handleCustomUniversalLoraSubmit`（CivitaiModal.tsx:326）把任何含 `/` 的输入都当 HF 仓库 ID 走 `fetchHuggingFaceModelInfo`，完整直链 URL（含 Civitai/HF resolve 链接）会被错误地当 repo 查询而失败。绕过方式：HF 仓库 ID 可被解析，再在 LoRA 节点的 `lora_name` 控件里改写成完整直链 URL（节点控件本就允许自由文本，path 会原样透传） | 📋 待修（建议：识别 `https?://` 前缀直接作为 path 选用） |
| F03 | **HF 模型分类过严**：`XLabs-AI/flux-lora-collection` 等带 `LoRA` 标签的仓库可过校验；`alimama-creative/FLUX.1-Turbo-Alpha`（单文件 LoRA 但 HF 未打 lora 标签）被分类为 Checkpoint 遭拒（「查询返回的资源不是 LoRA」） | 📋 待修（建议：tags 无 lora 时按 siblings 中 safetensors + base_model 标签辅助判定） |
| F04 | HF token 池第 1 个 key 疑似失效：`/api/huggingface/model-info` 对部分仓库返回上游 401 `Invalid username or password`（server 会附带 HF_TOKEN；换用池内其余 key 或匿名访问可恢复）。验收 HF 时注意 keyPool 轮换日志 | 📋 待核实 |
| F05 | LoRA Hub「新建节点」方式加入的 LoRA 节点不带连线，请求会发 `loras: []`（无效证据）；必须用「选用 LoRA · 保留当前底模」接入现有链 | ✅ 已在 Sogni 重做中规避并记录 |
| G01 | LLM 深度思考推理节点 / PromptRefinerNode 不在「添加节点」面板（ModernToolDock 固定清单），只能经工作流预设载入 | 📋 记录未修（产品决策） |
| G02 | SenseNova 生图在本应用中按设计走 OpenAI 兼容中转通道，非独立引擎 | 📋 记录（符合设计的说明已加在参数面板） |
